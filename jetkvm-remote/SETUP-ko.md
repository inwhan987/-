# 원격KVM 설치 가이드

JetKVM 기기를 새로 산 사람이 이 앱으로 **외부(LTE·다른 집·회사)에서 접속**할 수 있게
만드는 전체 순서입니다.

집 안(같은 와이파이)에서만 쓸 거라면 [1단계](#1단계-기기-기본-설치)와
[5단계](#5단계-앱에-기기-등록)만 하면 됩니다. 나머지는 외부 접속용이에요.

---

## 왜 설정이 두 갈래인가 (먼저 읽어주세요)

외부에서 연결될 때 **서로 다른 두 경로**가 동시에 필요합니다. 하나만 되면 연결이
완성되지 않아요.

| 경로 | 담당 | 없으면 생기는 증상 |
|---|---|---|
| **Tailscale Funnel** | 로그인 + 연결 협상(신호) | **"인증 중"에서 바로 실패** |
| **공유기 포트포워딩** | 실제 영상·키보드·마우스 데이터 | **"연결 중"에서 멈춤** |

쉽게 말해 **Tailscale = 약속을 잡는 통로, 포트포워딩 = 실제로 데이터가 다니는 길**
입니다.

> **왜 Tailscale만으로는 안 되나?**
> JetKVM은 커널 TUN이 없어서 Tailscale이 `userspace-networking` 모드로 동작합니다.
> 이 모드는 `100.x` 주소로 들어오는 연결을 받지 못하고, Funnel을 통과한 트래픽만
> 기기에 도달합니다. 그런데 Funnel은 HTTPS만 중계하므로 WebRTC 영상(UDP)은 지나갈
> 수 없어요. 그래서 영상 경로는 따로 열어줘야 합니다.

---

## 준비물

- JetKVM 기기, 랜선, 전원
- 기기를 연결할 **공유기 관리자 접근 권한** (포트포워딩 설정용)
- Tailscale 계정 (무료)
- 안드로이드 폰 (또는 Windows/macOS/Linux PC)

---

## 1단계: 기기 기본 설치

1. JetKVM을 제어할 PC의 HDMI·USB에 연결하고, 랜선과 전원을 꽂습니다.
2. 같은 와이파이에 있는 PC 브라우저에서 기기 웹 UI에 접속합니다.
   (주소는 기기 화면이나 공유기의 DHCP 목록에서 확인)
3. **로컬 비밀번호를 설정**합니다. 이 비밀번호를 나중에 앱에 입력합니다.
4. 기기의 **사설 IP를 고정**해두세요. 공유기 설정에서 이 기기의 MAC 주소에
   IP를 고정 할당(DHCP 예약)하면 됩니다.
   - ⚠️ 이걸 안 하면 재부팅 후 IP가 바뀌면서 4단계 포트포워딩이 깨집니다.
   - 예: `192.168.0.125`

이 시점에서 **같은 와이파이 안에서는** 앱으로 접속 가능합니다
([5단계](#5단계-앱에-기기-등록)에서 주소에 이 사설 IP를 넣으면 됨).

---

## 2단계: 기기에 SSH 접속

앞으로의 단계에서 기기에 명령어를 몇 개 입력해야 합니다.

기기 웹 UI 설정에서 SSH를 켜고, PC에서 접속합니다.

```bash
ssh root@192.168.0.125     # 1단계에서 고정한 사설 IP
```

---

## 3단계: Tailscale 설치 + Funnel 켜기 (신호 경로)

기기에 SSH로 접속한 상태에서:

```bash
# Tailscale 설치 (기기에 이미 있으면 생략)
tailscale up

# 화면에 뜨는 URL을 브라우저로 열어 계정에 로그인/승인
```

로그인이 끝나면 **Funnel을 켭니다.** 이게 외부에서 기기 웹 UI에 접근할 수 있게
해주는 부분입니다.

```bash
# 기기 웹 UI 포트를 공개 HTTPS 주소로 노출
tailscale funnel 80
```

> 기기 웹 UI가 80이 아닌 다른 포트면 그 번호를 넣으세요.

**주소 확인:**

```bash
tailscale status
```

`something.your-tailnet.ts.net` 형태의 주소가 나옵니다.
**이 주소를 적어두세요** — 5단계에서 앱에 입력합니다.

**확인 방법:** 폰의 와이파이를 끄고 **LTE 상태에서** 브라우저로
`https://적어둔주소.ts.net` 에 접속해보세요. 기기 로그인 화면이 뜨면 성공입니다.

---

## 4단계: 공유기 포트포워딩 (영상 경로)

### 4-1. 기기가 쓰는 포트 범위 확인

기기에 SSH로 접속해서:

```bash
cat /proc/sys/net/ipv4/ip_local_port_range
```

보통 이렇게 나옵니다:

```
32768	60999
```

> 이 값은 리눅스 기본값이라 대부분의 JetKVM에서 동일합니다. 다르게 나오면
> **본인 기기에 나온 값**을 쓰세요. WebRTC는 연결할 때마다 이 범위 안에서
> 포트를 무작위로 고르기 때문에, 포트 하나가 아니라 **범위 전체**를 열어야 합니다.

### 4-2. 공유기에 포트포워딩 등록

공유기 관리자 페이지 → 포트포워딩(가상서버/NAT) 메뉴에서:

| 항목 | 값 |
|---|---|
| 프로토콜 | **UDP** (TCP는 열지 마세요) |
| 외부 포트 | `32768` ~ `60999` |
| 내부 포트 | `32768` ~ `60999` (외부와 **동일하게**) |
| 대상 IP | 기기 사설 IP (예: `192.168.0.125`) |

> **DMZ보다 포트포워딩을 권장합니다.** DMZ는 기기의 모든 포트(SSH·웹 UI 포함)를
> 인터넷에 통째로 노출시킵니다. 위 설정은 UDP 그 범위만 열어서 훨씬 안전해요.

> 외부/내부 포트 번호를 **다르게 바꾸면 안 됩니다.** 기기가 알려주는 포트를
> 그대로 써야 연결됩니다.

### 4-3. 공인 IP 확인

기기에 SSH로 접속해서:

```bash
curl -4 -s ifconfig.me
```

`121.190.100.246` 같은 값이 나옵니다. **이 주소를 적어두세요** — 5단계에서
앱에 입력합니다.

> ⚠️ 인터넷 회선이 **유동 IP**면 이 값이 가끔 바뀝니다. 바뀌면 앱에서
> 기기 편집 → 공인 IP를 새 값으로 고쳐주세요. 자주 바뀌어서 번거로우면
> 통신사에 고정 IP를 신청하거나 DDNS를 쓰는 방법이 있습니다.

---

## 5단계: 앱에 기기 등록

앱을 설치하고 **+ 기기 추가**를 누른 뒤:

| 입력칸 | 넣을 값 |
|---|---|
| **이름** | 아무거나 (예: `사무실 PC`) |
| **주소 (호스트 / URL)** | 3단계의 `ts.net` 주소 |
| **비밀번호** | 1단계에서 설정한 기기 로컬 비밀번호 |
| **공인 IP** | 4-3단계에서 확인한 공인 IP |

> 같은 와이파이 안에서만 쓸 거면 **주소**에 기기 사설 IP를 넣고
> **공인 IP는 비워두면** 됩니다.

**저장 → 접속**을 누르면 연결됩니다.

---

## 6단계: 연결 확인

폰의 **와이파이를 끄고 LTE 상태에서** 접속해보세요. 화면이 나오면 완료입니다.

화면 왼쪽 위에 노란/빨간 점이 깜빡이면 통신 지연이 큰 상태입니다
(평소엔 아무것도 안 뜹니다).

---

## 문제 해결

### "인증 중"에서 실패한다

**신호 경로(Tailscale) 문제입니다.**

1. LTE 상태의 폰 브라우저로 `https://주소.ts.net` 접속 → 로그인 화면이 뜨나요?
   - 안 뜨면 → 3단계 Funnel 설정 문제. 기기에서 `tailscale funnel status` 확인
2. 뜬다면 → 앱에 입력한 **비밀번호**를 확인하세요

### "연결 중"에서 멈춘다 / 시간 초과

**영상 경로(포트포워딩) 문제입니다.** 신호는 잘 가고 있다는 뜻이에요.

1. 앱에 **공인 IP를 입력했는지** 확인 (기기 편집에서 확인)
2. 공인 IP가 바뀌지 않았는지 확인:
   ```bash
   curl -4 -s ifconfig.me     # 기기에서 실행
   ```
3. 포트포워딩이 **UDP**이고 **범위가 맞는지**, **대상 IP가 기기 사설 IP인지** 확인
4. 기기 사설 IP가 바뀌지 않았는지 확인 (1단계의 DHCP 예약이 풀렸을 수 있음)

### 자세한 원인을 보고 싶을 때

**앱 쪽 로그** — 연결 실패 화면에서 **"로그 복사"** 버튼을 누르면 전체 진단
정보(연결 단계별 시각, ICE 상태, 주고받은 SDP)가 복사됩니다.

로그에서 볼 부분:

```
trickled candidate: ... 192.168.0.125 ...   ← 기기가 알려준 사설 주소
```

이 줄이 **아예 없으면** 신호 경로 문제이고, 있는데도 연결이 안 되면 영상 경로
문제입니다.

**기기 쪽 로그** — SSH로 접속해서:

```bash
tail -f /userdata/jetkvm/last.log
```

접속을 시도하면서 실시간으로 보면 됩니다.

- `Failed to ping without candidate pairs` → 이 줄 자체는 정상이며 성공할 때도
  나옵니다. 무시하세요.
- 그 직후 `connecting canceled by caller` 가 뜨면 → 영상 경로가 막힌 것

---

## 보안 참고

- **포트포워딩은 UDP 범위만 여세요.** DMZ나 TCP 개방은 기기의 SSH·웹 UI를
  인터넷에 노출시킵니다.
- 기기 **로컬 비밀번호를 반드시 강하게** 설정하세요. Funnel 주소는 공개
  인터넷에서 접근 가능합니다.
- 앱에 저장된 비밀번호는 현재 기기 내부 저장소에 **암호화 없이** 보관됩니다
  (`src/storage/devices.ts`). 폰 분실 시를 대비해 기기 비밀번호는 다른 곳에
  쓰지 않는 것으로 설정하세요.
- 영상·입력 데이터 자체는 WebRTC의 DTLS-SRTP로 암호화되어 전송됩니다.

---

## 부록: 이 구성을 하나로 합칠 수 없나?

**Tailscale 하나로 통합** — 불가능합니다. 기기가 `userspace-networking` 모드라
`100.x` 주소로 들어오는 UDP를 받지 못하고, Funnel은 HTTPS만 중계해서 영상이
지나갈 수 없습니다.

**포트포워딩 하나로 통합** — 기술적으로는 가능하지만 **권장하지 않습니다.**
기기 웹 포트까지 포워딩하고 앱 주소를 `http://공인IP:포트`로 넣으면 동작은
하지만, 로그인 비밀번호가 **암호화 없이 인터넷을 지나갑니다.** Tailscale Funnel이
제공하는 HTTPS 인증서를 포기하는 셈이라 보안상 나쁜 선택입니다.

지금의 **Funnel(신호) + 포트포워딩(영상)** 조합이 실제로 검증된 구성입니다.
